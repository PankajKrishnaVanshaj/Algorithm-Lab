What is a data structure?

A data structure is a way to organize and manage data so operations can be performed efficiently. The right structure depends on how data is accessed, inserted, removed and searched. This lab focuses on three foundational linear structures.

Stack: Last In, First Out

A stack follows LIFO order: the most recently added item is the first one removed. Push adds an item to the top, pop removes the top item, and peek reads the top without removing it. These operations are O(1) in a typical array-backed or linked implementation. Stacks are used in function calls, undo systems, parsing and depth-first search.

Queue: First In, First Out

A queue follows FIFO order: the earliest inserted item is removed first. Enqueue adds an item at the rear, while dequeue removes an item from the front. A well-designed circular-buffer or linked implementation can perform both in O(1). Queues are used in task scheduling, buffering, breadth-first search and request processing.

Singly linked list

A singly linked list contains nodes. Each node stores a value and a reference to the next node. Inserting at the head is O(1). Searching for a value is O(n). Appending is O(n) without a tail reference and can be O(1) when a tail reference is maintained. Deleting a value usually requires finding its previous node first.

Operation costs depend on the implementation

A stack backed by a dynamic array can usually append and remove its last element in amortized O(1) time. Occasionally an array resize copies existing elements, so a single push may take longer even though the long-run average remains constant. A linked-list-backed stack avoids array capacity changes but allocates a node for each insertion and follows pointers between nodes.

A queue should not be implemented by repeatedly shifting every item in a plain array if constant-time dequeue is important. A circular buffer can keep a front index and rear index, wrapping around when it reaches the end. A linked queue can maintain both head and tail references. These designs explain why the abstract FIFO rule does not, by itself, determine the efficiency of an implementation.

Keep the structure's invariants intact

For a stack, only the top item may be removed; popping an empty stack must be handled as an underflow condition. For a queue, removal occurs at the front and insertion at the rear; an empty queue should have a consistent empty-state representation. For a singly linked list, the head points to the first node and the final node's next reference is null. Inserting or deleting a node means updating the links that lead into and out of that position.

Try sequences that test boundaries rather than only happy paths: push and pop until empty, dequeue from an empty queue, append to an empty list, prepend several nodes, delete the head, delete the tail, search for a missing value, and delete a value that occurs more than once. Boundary testing is how an abstract diagram becomes a useful implementation habit.

What this particular demonstration models

The workspace presents values in a compact visual model so you can concentrate on operation order. Its linked-list view represents the logical node sequence for learning; the displayed values are held by the page's state model rather than allocated as a real pointer-based memory structure. This is deliberate: the diagram explains head/tail relationships and operation effects, but it is not a memory profiler.

When translating the idea into code, define the node shape explicitly, decide whether you maintain a tail pointer, and write tests for empty, one-node and repeated-value cases. A design with a tail pointer can make append constant time, but then every deletion or reset that changes the final node must keep that pointer correct.

Frequently asked questions

What is the difference between a stack and a queue?

A stack removes the newest item first (LIFO), while a queue removes the oldest item first (FIFO).

Are stack push and pop O(1)?

They are O(1) in common implementations when the stack has available capacity or uses a linked representation. Dynamic-array resizing can occasionally make an individual push more expensive, though append is amortized O(1).

Is a linked list faster than an array?

Neither is universally faster. Linked lists support O(1) insertion at a known node or at the head, but indexed access is O(n). Arrays provide O(1) indexed access and often better cache locality.
