How Binary Search works

Binary Search maintains a search interval with a left and right boundary. It checks the middle element. If the middle value equals the target, the search succeeds. If the target is smaller, the algorithm continues in the left half; if larger, it continues in the right half. Each valid decision reduces the remaining interval by roughly half.

Why the input must be sorted

The algorithm can discard half the range only because the values are ordered. If the midpoint is smaller than the target in an ascending array, every value to its left is also too small. Without sorted order, that inference is invalid and the algorithm could discard the target.

Example walkthrough

For the sorted array [3, 8, 12, 17, 21, 29, 34] and target 21, the first midpoint is 17. Since 21 is greater, the search continues to the right. The next midpoint is 29. Since 21 is smaller, the range moves left, and the next check reaches 21. The target is found after three midpoint checks.

Complexity and limitations

Binary Search takes O(log n) time because the remaining range is halved after each comparison. Iterative Binary Search uses O(1) auxiliary space. The data must support efficient access to its middle element; arrays are a natural fit, while a linked list does not provide constant-time indexed access.

Common edge cases

Test a target at the first or last position, a missing target below or above the range, a one-element array, an empty array and duplicate values. When duplicates exist, ordinary Binary Search may return any matching occurrence unless the implementation is specifically designed to find the first or last match.

The invariant that makes Binary Search correct

Binary Search is easiest to reason about when you state what remains possible after every iteration. In an inclusive interval implementation, the target—if it exists—must be somewhere between indexes left and right. Every discarded index is known not to contain the target because the array is sorted. The loop ends when the target is found or when left > right, which means there is no candidate index remaining.

while (left <= right) {
  const mid = left + Math.floor((right - left) / 2);
  if (values[mid] === target) return mid;
  if (values[mid] < target) left = mid + 1;
  else right = mid - 1;
}
return -1;

The midpoint expression above avoids adding two potentially large indexes before dividing. In JavaScript arrays are limited by runtime implementation constraints, but this form is also a widely used defensive habit in lower-level languages where integer overflow is a practical concern.

Trace a second example by hand

Consider [3, 8, 12, 17, 22, 29, 35] and search for 22, using zero-based indexes. The interval begins at 0 through 6. The midpoint is index 3, whose value is 17; because 22 is larger, the next interval begins at index 4. The next midpoint is index 5, whose value is 29; because 22 is smaller, the right boundary moves to index 4. The final midpoint is index 4, where 22 is found. Three comparisons are enough for seven values.

For a missing target such as 23, the same decisions eventually create an empty interval. The algorithm reports absence rather than inventing an insertion index. A separate lower-bound or upper-bound search can be used when the desired result is the first position not less than a target, or the first position greater than it.

Duplicates and insertion positions

Ordinary Binary Search only promises to find a matching occurrence. If a sorted array contains [2, 4, 4, 4, 9], a standard implementation might return any of the three indexes holding 4 depending on its midpoint choices. To find the first match, continue searching left after a match and remember the candidate. To find the last match, continue searching right. These are boundary-search variants, not just cosmetic changes.

Do not apply Binary Search to an array that changes while the search runs unless the algorithm's correctness assumptions are preserved. A mutation can invalidate the sorted order or shift indexes and make earlier comparisons stale. If data must be searched repeatedly, include the cost of sorting or maintaining order in the overall design.

Frequently asked questions

Can Binary Search work on an unsorted array?

Not correctly in its standard form. The array must be sorted according to the same ordering used by the search.

Why is Binary Search O(log n)?

Each comparison eliminates approximately half of the remaining candidates, so the number of steps grows logarithmically with input size.

Is Binary Search faster than Linear Search?

For large sorted arrays, Binary Search usually needs far fewer comparisons. Linear Search works on unsorted data and can be preferable for very small collections or data structures without efficient random access.
