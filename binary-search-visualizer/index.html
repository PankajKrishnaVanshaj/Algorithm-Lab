How Binary Search works

Binary Search maintains a search interval with a left and right boundary. It checks the middle element. If the middle value equals the target, the search succeeds. If the target is smaller, the algorithm continues in the left half; if larger, it continues in the right half. Each valid decision reduces the remaining interval by roughly half.

Why the input must be sorted

The algorithm can discard half the range only because the values are ordered. If the midpoint is smaller than the target in an ascending array, every value to its left is also too small. Without sorted order, that inference is invalid and the algorithm could discard the target.

Example walkthrough

For the sorted array [3, 8, 12, 17, 21, 29, 34] and target 21, the first midpoint is 17. Since 21 is greater, the search continues to the right. The next midpoint is 29. Since 21 is smaller, the range moves left, and the next check reaches 21. The target is found after three midpoint checks.

Complexity and limitations

Binary Search takes O(log n) time because the remaining range is halved after each comparison. Iterative Binary Search uses O(1) auxiliary space. The data must support efficient access to its middle element; arrays are a natural fit, while a linked list does not provide constant-time indexed access.

Common edge cases

Test a target at the first or last position, a missing target below or above the range, a one-element array, an empty array and duplicate values. When duplicates exist, ordinary Binary Search may return any matching occurrence unless the implementation is specifically designed to find the first or last match.

Frequently asked questions

Can Binary Search work on an unsorted array?

Not correctly in its standard form. The array must be sorted according to the same ordering used by the search.

Why is Binary Search O(log n)?

Each comparison eliminates approximately half of the remaining candidates, so the number of steps grows logarithmically with input size.

Is Binary Search faster than Linear Search?

For large sorted arrays, Binary Search usually needs far fewer comparisons. Linear Search works on unsorted data and can be preferable for very small collections or data structures without efficient random access.
