Quicksort Partition Explained: A Step-by-Step Array Example

Partitioning is the key operation in Quicksort. It rearranges an array around a pivot so values on one side are smaller and values on the other side are larger or equal, allowing the algorithm to solve smaller subproblems.

By Pankaj KrishnaVanshaj · BCA, Chhatrapati Shahu Ji Maharaj University, Kanpur · Updated November 13, 2026

What does partition do?

A partition routine chooses a pivot and rearranges values so that the pivot reaches a position consistent with the selected partition rule. In a Lomuto-style partition, one common rule places values less than or equal to the pivot before it and larger values after it. Other schemes, such as Hoare partitioning, use different pointer rules and return a boundary rather than necessarily placing the pivot in its final sorted position.

That distinction matters: partition variants are not interchangeable unless the surrounding Quicksort recursion uses the matching boundaries.

Walk through one partition

Consider the array [9, 3, 7, 1, 8, 2, 5] and choose the last value, 5, as the Lomuto pivot. Scan the array from left to right (excluding the pivot). Keep a boundary index for the region known to contain values less than or equal to 5.

  1. Start with boundary −1.
  2. See 9: it is greater than 5, so leave it in the right region.
  3. See 3: it is at most 5; advance the boundary and swap 3 into the left region.
  4. See 7 and 8: both are greater than 5, so continue.
  5. See 1 and 2: advance the boundary and move each into the left region.
  6. Finally swap the pivot 5 just after the left region.

The resulting arrangement is [3, 1, 2, 5, 8, 7, 9]. The left partition contains values at most 5, the pivot is at index 3, and the right partition contains values greater than 5. The two partitions are not yet internally sorted.

Lomuto partition pseudocode

function partition(array, low, high) {
  const pivot = array[high];
  let boundary = low - 1;

  for (let scan = low; scan < high; scan++) {
    if (array[scan] <= pivot) {
      boundary++;
      [array[boundary], array[scan]] =
        [array[scan], array[boundary]];
    }
  }

  [array[boundary + 1], array[high]] =
    [array[high], array[boundary + 1]];
  return boundary + 1;
}

This example uses the last element as pivot. Production implementations may choose a middle, random or median-of-three pivot to reduce the chance of consistently poor partitions.

Why partition quality changes Quicksort performance

Each partition scans a subarray, so one partition pass takes linear time in the size of that subarray. If partitions are reasonably balanced, recursion has about logarithmic depth and Quicksort runs in O(n log n)O(n²).

Duplicate-heavy inputs also deserve attention. Three-way partitioning can group values equal to the pivot and avoid repeatedly processing them as ordinary left/right elements.

Common partition mistakes

  • Using an inclusive or exclusive boundary inconsistently in recursive calls.
  • Mixing Lomuto and Hoare return-value conventions.
  • Forgetting that partitioning does not fully sort either side.
  • Assuming a pivot is always in its final position when using a partition scheme that only returns a split boundary.
  • Ignoring recursion depth and worst-case inputs.

Lomuto partition in JavaScript

The following implementation matches the last-element-pivot walkthrough on this page. It maintains a boundary for values no greater than the pivot. When the scan finds such a value, it advances the boundary and places the value into the left region. At the end, it places the pivot directly after that region and returns the pivot's final index.

function partition(values, low, high) {
  const pivot = values[high];
  let boundary = low - 1;

  for (let scan = low; scan < high; scan++) {
    if (values[scan] <= pivot) {
      boundary++;
      [values[boundary], values[scan]] =
        [values[scan], values[boundary]];
    }
  }

  [values[boundary + 1], values[high]] =
    [values[high], values[boundary + 1]];
  return boundary + 1;
}

After the function returns, values before the pivot index are less than or equal to the pivot and values after it are greater. The two sides still need recursive sorting. This exact return-value contract belongs to Lomuto partitioning; a Hoare-style partition returns a split boundary with different recursion rules.

Why many equal values need care

With a two-way partition, equal values may be repeatedly sent to one side depending on the comparison rule. If a data set contains many copies of the pivot, repeated work can be wasted. Three-way partitioning divides the range into values smaller than the pivot, equal to the pivot and greater than the pivot. The equal region is already finished and is excluded from future recursive calls.

Three-way partitioning is especially useful when duplicate keys are common, but it is a different algorithmic design from the single-pivot Lomuto example above. A trace should identify which partition scheme is being demonstrated, because code and complexity details depend on its rules.

Connect partitioning to the full recursive algorithm

A typical Quicksort call first stops when the subarray has zero or one element. Otherwise, it partitions the subarray, obtains a pivot index, recursively sorts the part before the pivot and recursively sorts the part after it. The pivot is not included in either recursive range because Lomuto has already placed it in its final sorted position relative to that partition.

For safer production implementations, pivot selection can be randomized or based on a sample such as the median of three values. An implementation may also switch to Insertion Sort for tiny partitions or use an introspective fallback when recursion becomes too deep. Such safeguards change practical behavior while preserving the high-level divide-and-conquer idea.

Practice questions

  3. Why can an array of identical values be a poor case for a basic two-way partition?
  4. Why must the recursion boundaries match the selected partition scheme?

Frequently asked questions

Does partition sort the array?

No. It places values into partitions relative to a pivot. Quicksort recursively sorts the partitions afterward.

Is the pivot always the final element?

No. The pivot strategy depends on the implementation. This walkthrough uses the last element for a Lomuto-style partition.

What is the time complexity of one partition pass?

A partition pass scans its current subarray once, so it takes linear time in the subarray length.
