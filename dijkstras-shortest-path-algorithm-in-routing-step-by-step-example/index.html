Dijkstra's Shortest Path Algorithm: A Step-by-Step Example

Dijkstra's algorithm finds shortest-path distances from one starting vertex in a graph with non-negative edge weights. It is widely used as a foundation for routing and network pathfinding explanations.

An educational guide from PANKRI · Published November 3, 2026

The shortest-path problem

A weighted graph contains vertices (locations or states) connected by edges (routes or transitions). Each edge has a weight such as distance, cost or delay. The single-source shortest-path problem asks for the minimum total weight from one start vertex to every reachable vertex, or to a selected destination.

Dijkstra's algorithm solves this problem when edge weights are non-negative. It does not require the graph to be a road map; it works on any suitable weighted graph.

A small routing example

Imagine a graph with routes A–B (4), A–C (3), B–D (5), B–E (2), C–E (4), C–F (6), D–G (3), E–G (2) and F–G (2). Starting at A, the tentative distance to A is 0 and every other vertex begins at infinity.

  1. Visit A. Set B to 4 and C to 3.
  2. Choose the unvisited vertex with the smallest tentative distance: C (3). Relax C–E to 7 and C–F to 9.
  3. Choose B (4). Relax B–D to 9 and B–E to 6, improving E from 7 to 6.
  4. Choose E (6). Relax E–G to 8.
  5. Choose G (8) next because it has the smallest remaining tentative distance. Its shortest distance from A is now settled at 8.
  6. D and F remain at tentative distance 9; their routes to G do not improve the known distance of 8.

One shortest route is A → B → E → G with total weight 4 + 2 + 2 = 8. Another equal-cost route may exist in other graphs; predecessor tracking reconstructs one chosen shortest path.

What does edge relaxation mean?

For an edge from u to v with weight w, relaxation tests whether distance[u] + w is less than the current distance[v]. If it is, update the distance and record u as v's predecessor. This is the central operation that gradually improves tentative routes.

if (distance[u] + weight < distance[v]) {
  distance[v] = distance[u] + weight;
  previous[v] = u;
}

Why use a priority queue?

A simple implementation can repeatedly scan all unvisited vertices to find the smallest tentative distance. A more scalable implementation uses a min-priority queue so the next vertex can be selected efficiently. With an adjacency list and a binary heap, a common complexity bound is O((V + E) log V), with details depending on the priority-queue implementation and how outdated entries are handled.

Limitations and common mistakes

  • Do not use ordinary Dijkstra when edges can have negative weights; use an algorithm designed for that setting, such as Bellman–Ford.
  • Distinguish an unreachable vertex (infinite distance) from a vertex whose shortest distance is zero.
  • Use the correct graph representation and account for directed versus undirected edges.
  • Store predecessors if you need to reconstruct a path, not just its distance.
  • Do not confuse the visualizer's operation counters with a hardware benchmark.

Frequently asked questions

Does Dijkstra work with negative weights?

No. Dijkstra relies on non-negative edge weights. Negative-weight shortest paths require a different algorithm, such as Bellman–Ford.

What does relaxation do?

It checks whether reaching a neighbor through the current vertex gives a shorter route. If so, it updates the neighbor distance and predecessor.

Does Dijkstra find one path or all distances?

The single-source version computes shortest distances to all reachable vertices. Keeping predecessor information lets the program reconstruct a shortest path to a selected destination.
