A visual way to understand algorithms

An algorithm is a finite sequence of well-defined steps used to solve a problem. Studying its behavior helps you choose an approach that is correct, efficient, and appropriate for the size and shape of your data.

QUICK REFERENCE

What does Big-O mean?

Big-O notation describes how an algorithm's resource use grows as input size increases. It is commonly used to discuss time and space complexity, especially for large inputs.

Complexity Common name Example
O(1) Constant Array index access
O(log n) Logarithmic Binary search
O(n) Linear Linear search
O(n log n) Linearithmic Merge sort (typical)
O(n²) Quadratic Bubble sort (average/worst)
COMMON QUESTIONS

Algorithm Lab FAQ

Is PANKRI Algorithm Lab free to use?

Yes. The visualizers on this page are free to use and do not require an account.

Are my inputs uploaded to a server?

No. The calculations and visualizations run locally in your browser. This page does not send the values you enter to a PANKRI application server.

Are the operation counts the same as execution time?

No. Comparisons, swaps, writes, and visits are educational operation counts. Actual runtime also depends on implementation details, browser behavior, device hardware, and input characteristics.

Why does Binary Search require sorted data?

Binary Search eliminates half of the remaining search range after each comparison. That decision is only valid when the values are ordered. This visualizer sorts a working copy of your input before running Binary Search.

Which sorting algorithm is always fastest?

There is no single sorting algorithm that is fastest for every input and situation. Quick Sort is often fast in practice, Merge Sort provides predictable O(n log n) time, and simpler algorithms can be useful for small or nearly sorted inputs.
