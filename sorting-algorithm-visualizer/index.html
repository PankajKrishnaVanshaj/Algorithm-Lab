What is a sorting algorithm?

A sorting algorithm rearranges a collection of values into a chosen order, usually ascending or descending. Sorting is a foundational computer science task because ordered data can make searching, reporting, deduplication and later processing easier. Different algorithms make different trade-offs in speed, memory use, stability and implementation complexity.

Compare the five algorithms

Bubble Sort repeatedly compares adjacent values and swaps them when they are out of order. Selection Sort repeatedly selects the smallest remaining value and places it next. Insertion Sort grows a sorted prefix by inserting each new value into its correct position. Merge Sort divides the input, sorts each half and merges the results. Quick Sort partitions values around a pivot and recursively sorts the partitions.

Understand comparisons, swaps and writes

A comparison checks the relationship between values. A swap exchanges two positions. A write places a value into an array position. These counters describe the work represented by this visualizer; they are not a universal measure of elapsed time. Implementations can count operations differently, and real runtime depends on the browser, device, input and code.

Sorting complexity at a glance

Bubble Sort and Selection Sort take O(n²) comparisons in typical and worst-case analysis. Insertion Sort is O(n) on already sorted input and O(n²) in average and worst cases. Merge Sort has O(n log n) time in best, average and worst cases, with additional memory for merging. Quick Sort is O(n log n) on average and O(n²) in the worst case, depending on pivot choices and partition behavior.

A worked trace: sorting [5, 1, 4, 2]

For Bubble Sort, the first pass compares neighboring values from left to right. It compares 5 with 1 and swaps them, then compares 5 with 4 and swaps again, then compares 5 with 2 and swaps once more. After that pass, the array is [1, 4, 2, 5]. The largest value has reached its final position, but the remaining prefix is not yet sorted. A second pass moves 4 behind 2, producing [1, 2, 4, 5].

Insertion Sort approaches the same input differently. It treats the first value as a sorted prefix, takes the next value, shifts larger prefix elements right, and inserts the value into the gap. After inserting 1, the prefix is [1, 5]; after inserting 4 it is [1, 4, 5]; inserting 2 gives the final order. The final result is the same, but the intermediate states and operation counts differ.

What to observe

  • When the input is already sorted, an optimized Bubble Sort can stop after a pass with no swaps.
  • Insertion Sort is often attractive for small or nearly sorted arrays because each new value may move only a short distance.
  • Merge Sort does predictable divide-and-merge work, but its temporary storage requirement is different from an in-place partitioning method.
  • Quick Sort behavior depends strongly on pivot selection and partition balance.

Stability, memory and the meaning of equal values

A stable sort preserves the original relative order of records whose sort keys compare equal. Imagine sorting students by score while keeping their original registration order for ties. Stability matters when records carry data beyond the value used for comparison. Bubble Sort and Insertion Sort are stable in their usual textbook implementations when equal values are not needlessly swapped. Merge Sort can be stable when the merge step chooses the left value first on equality. A common in-place Quick Sort and Selection Sort implementation is not stable.

“In place” is also a separate property from speed. Selection Sort, Insertion Sort and common Quick Sort variants rearrange the input array directly, although recursion still consumes stack space. Merge Sort for arrays commonly needs an auxiliary array proportional to the input length. These distinctions matter when memory is constrained or the original data must remain unchanged.

Make a fair comparison in the visualizer

To compare algorithms meaningfully, start each run from the same sequence. A useful experiment records the array length, input pattern, algorithm, comparison count, swap count and write count. Repeat with sorted, reverse-sorted, random and duplicate-heavy arrays. Keep the input size fixed when comparing input patterns, then increase the size to see how the work grows.

The lab records logical operations from its own JavaScript implementations. It does not isolate CPU scheduling, browser rendering, garbage collection, JIT compilation or device load, so its counters must not be read as milliseconds or as a ranking of production language libraries. Operation definitions are implementation-specific: a merge write and a swap are not interchangeable units of real machine cost.

Frequently asked questions

Which sorting algorithm should beginners learn first?

Bubble Sort is easy to trace because it compares neighboring values. Insertion Sort is also a useful teaching example because it shows how a sorted section can grow one value at a time. Learn them as concepts, then compare them with Merge Sort and Quick Sort.

Is Quick Sort always faster than Bubble Sort?

No algorithm is fastest for every input and implementation. Quick Sort is generally much more scalable on large inputs on average, but its worst case is quadratic. Small arrays, nearly sorted data, pivot selection and implementation details can change observed results.

Does the visualizer benchmark actual CPU speed?

No. It visualizes algorithm steps and counts selected operations. It does not provide a controlled performance benchmark. Use dedicated benchmarking methods if you need reliable runtime measurements.
